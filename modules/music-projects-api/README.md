# Music Projects API

In-development PHP 8.5 / Laravel 13 adapter for the Projects core owner, including checkpoint/autosave writes, recovery and confirmed portable imports. Installing the package does not enable its endpoints; enable the module explicitly through the host module manager and enable `music-projects` separately. Domain persistence, policies and portable manifest verification remain in core. No migrations or domain models live in this adapter.

The contract in [openapi/projects.json](openapi/projects.json) describes the implemented query and command endpoints under `/api/v1/music-projects/workspaces/{workspace}`. A host-issued Sanctum bearer token requires `music.projects.read` or, for preview, `music.projects.preview`; mutation endpoints require `music.projects.write`. Recovery also requires `music.projects.read` because it returns historical source content. Token ability alone never grants owner permission. Stateful browser requests require the host's Sanctum and CSRF configuration; the package does not publish a token-issuance endpoint.

Read current sessions with `GET /sessions`, a project with `GET /sessions/{uuid}`, history with `GET /sessions/{uuid}/revisions`, or a portable backup with `GET /sessions/{uuid}/manifest`. `version` selects a historical revision. Collections accept `page[size]` (1–100) and opaque `page[after]` cursors returned in `meta.next_cursor`; keep the same workspace/collection/filter when reusing them. `templates=1` and `templates=0` filter the catalogue. Collections return lightweight metadata without session documents or asset references; full reads and exports independently revalidate media access. Responses use `{data, meta}`; all include a request ID and prevent shared caching.

`POST /sessions/{uuid}/import-preview` accepts `{"manifest":"<portable JSON string>"}`. It checks the destination write policy, supported schemas, checksum and referenced media, returns a summary and never writes a destination or grants permission for later import. Unsupported schemas produce 422; malformed portable JSON produces 400. Missing credentials produce 401, missing scope/policy 403, unavailable resources 404, rate limits 429 (with Retry-After), and disabled core 503. Errors use redacted Problem Details, including field violations and a request ID. Unexpected errors remain 500 without traces or internal messages. The default authenticated limit is 60 requests per minute.

Not yet delivered: persistent push/SSE delivery, contract examples/registry integration, quotas, async operation APIs and complete supported-runtime acceptance. Capability discovery reports these unavailable. Audio execution, recording/device control and sample scheduling require a compatible local runtime. This package is not a completed implementation of host issue #7.

Run `composer install`, `composer test` and `composer test:coverage` from this directory. The core dependency accepts its development branch until a compatible version is published; the explicit Git repository resolves that branch without installing a PHP host.


`POST /sessions/{uuid}/checkpoints` saves `{title, document, autosave?, template?}`. It creates the first revision with `If-Match: "0"`; later saves require the quoted current version. `POST /sessions/{uuid}/recoveries` accepts `{source_version}` and writes an authorized historical document as a new non-autosave checkpoint. `POST /sessions/{uuid}/imports` confirms `{manifest}` into a new identity and requires `If-Match: "0"`.

Every command requires `Idempotency-Key` (1–128 visible ASCII characters) and `If-Match`. Missing preconditions return 428; malformed headers or bodies return 422. Stale revisions return 412 with reload/reconcile guidance; conflicting command-key reuse and changing an immutable template type return 409 with distinct problem types. Preserve the existing template flag when updating a template. An exact retry returns its original 201 result, ETag and immutable Location, even after newer revisions; it does not replace newer work. Never preflight a retry by checking the current ETag: core arbitrates the command log and precondition together. Changing a command requires a new key. Responses include the saved revision, quoted version ETag and a Location selecting that exact version. Native/audio execution remains unavailable.

Core owns permission rechecks on save/replay/recovery/import, media verification, revision locking, command fingerprints, transactional reference retention and commit-bound events. An earlier preview never authorizes confirmation after access is revoked. Failed database writes roll back the command and can be retried with the same key after recovery. Deploy this in-development adapter with the matching current Projects core; both typed conflict contracts are supplied by the owning core package; older core sources do not provide the complete outcome classification.

Capability identifier lists are extensible: clients should ignore unknown identifiers and select only explicitly supported operations and document schemas.


`GET /sessions/{uuid}/changes` provides a bounded polling feed of durable revision notices, including autosaves. It returns ascending versions, document checksums, UTC metadata times and flags without session documents, actor identities or media references. It uses the core owner query with two indexed database reads. These timestamps are never an audio clock. Token ability and project read permission are checked on every poll; a cursor grants no access.

Start with a full authorized `GET /sessions/{uuid}` (optionally `?version=N`) and persist the returned snapshot with `meta.changes_cursor`. Poll with `page[after]` set to that opaque cursor and `page[size]` between 1 and 100. Use the returned `meta.next_cursor` only after notices have been applied or an authoritative snapshot reloaded; persist state and cursor together so a local interruption cannot silently lose an update. Retrying the same cursor may repeat notices; deduplicate by project revision version. A document checksum alone is insufficient because metadata-only edits also create revisions. Use at least a five-second idle polling interval and honor rate-limit Retry-After guidance. Cursor strings may change without a version advancing; do not infer state from ciphertext equality.

Cursors use Laravel authenticated encryption with the host APP_KEY and include a purpose/schema plus the exact workspace/session and revision position. URL-encode them as query values. Malformed, tampered, wrong-purpose/schema, non-integer and cross-resource cursors return 422 without exposing their payload. Key changes may require a new snapshot unless the host configures compatible previous encryption keys. Installing encryption support never publishes routes; module enablement remains separate.

On `data.resync_required`, the page contains no partial notices and `meta.next_cursor` is null. Preserve local drafts for explicit reconciliation and fetch `links.snapshot`, which selects the exact upper revision observed by that poll. Resume from that snapshot's `meta.changes_cursor`. If the snapshot itself is unavailable or access is denied, show recovery failure; never substitute an older snapshot and assume synchronization succeeded. After authorized repair/recovery, obtain a new full snapshot. The feed does not merge drafts, repair damaged database rows, execute audio or provide continuous server push.
