# Music Media Library

Audio asset verification for Laravel 13 and PHP 8.5. Under development; implementation and remaining scope are tracked in [issue #62](https://github.com/liberusoftware/music-daw-laravel/issues/62).

Run `composer install`, then `composer test` or `composer test:coverage` in this directory. Tests use the shared Liberu package testbench.

Media-bearing session writes require the public `SessionMediaRetention` contract to retain references in the same active database connection and transaction as the revision. The host composes this with Media Library `MediaRetention`. The `music.media.retain` permission and per-asset read permission are required, including on replay. Older revision pins remain after autosave and recovery.

Retention protects shared content within a workspace. `OfflinePins::save` accepts a `SaveOfflinePin` command containing a caller-generated UUID, expected version, command key and asset UUIDs. Replacing the asset set with an empty list releases that device pin. Replays return the original immutable result without reapplying an older asset set or lease. `OfflinePins::get` returns the current version and assets. Pin ownership is actor and workspace scoped, even when the workspace policy allows multiple users.

Offline pin operations require `music.media.pin`, per-asset read permission and, for mutations, `music.media.retain`. An optional UTC expiry uses `YYYY-MM-DDTHH:MM:SSZ`; new leases must expire in the future. Omit it for permanent protection. Expired leases stop protecting bytes at their declared boundary; renewal requires the current version and a new command key. Expiry and release do not delete files, stop local recording or release session/pack/other-device references. `OfflinePinSaved` is dispatched after the encompassing transaction commits.

`QuarantineCleanup::collect` accepts `CollectCancelledUploads` for a workspace, with a default dry run, a UTC grace period of at least 24 hours, a limit of 1–100 chunks, and an optional numeric chunk cursor. It requires `music.media.collect` for the workspace and every selected upload. Reports contain schema-v1 chunk identities, a cutoff, declared bytes and a continuation cursor; they never expose private object paths. Declared bytes include already-missing chunks acknowledged during recovery and are not a measurement of physical disk space freed.

Pass `dryRun: false` to remove eligible cancelled-upload chunks. Storage failures preserve the ledger for retry, and retries acknowledge objects removed before a crash or database rollback. Cancellation is terminal and repeating it preserves its original grace period. Upload identities, provenance and status remain for audit. `QuarantineCollected` is dispatched after commit. Legacy cancellations receive a fresh grace period when upgrading. Only cancelled quarantine is collected; uploading and ready chunks, published audio, saved sessions and active pins are preserved.

Published-asset garbage collection and its shared-content retention checks remain pending. Projects provides historical revision retention backfill; operators must complete it before any future published-asset deletion is enabled.


`MediaPacks::save` accepts `SaveMediaPack` with workspace/pack UUID, name, asset UUIDs, declared `source`/`license`/`attribution`, expected version and command key. Each revision snapshots verified references and their original provenance, and retains its assets in the same transaction. Commands canonicalize membership; replays return their original revision without replacing newer membership. Up to 1,000 assets and a 4 MiB serialized document are accepted. `get` reads the latest or an explicit revision; `history` returns bounded revision summaries without loading full documents. `MediaPackSaved` is dispatched after commit. Old revisions keep their retention references.

Pack writes require `music.media.pack_write`, retention permission and per-asset read permission; reads/history require `music.media.pack_read`. Export/import also require `music.media.pack_export` / `music.media.pack_import` and the foundation `TransferAuthorizer` for schema `music-media-pack`, direction `export` / `import`. Missing transfer policy denies the operation.

Before export, `PackDistributionPolicy` reviews the exact immutable revision. Its default `GatePackDistribution` adapter uses `music.media.pack_distribute` with the full `MediaPack` document, so the host can review that revision's declared terms against all asset provenance. No approval is inferred from a checksum or a license string. Every exported asset additionally requires `music.media.distribute`, current read permission, verified availability and nonempty source/license/attribution. Internal collections may hold assets with incomplete provenance but cannot export them.

Portable schema-v1 manifests preserve pack terms, asset references and provenance, with a checksum and no private paths. `import` takes an explicit map from every source asset UUID to a distinct verified destination UUID. Audio metadata and provenance must match; it never fetches arbitrary URLs, trusts source workspace access or grants distribution rights. Imported packs start at revision 1 and must pass the destination distribution policy before export. These metadata manifests are also used by the ZIP transport below. Public distribution links and published-asset garbage collection remain unfinished.


`PackArchives::exportTo` writes a reviewed pack revision to a caller-owned writable stream and returns an immutable checksum/byte-count receipt. The ZIP contains `manifest.json` and one `assets/<sha256>.wav` object per unique checksum. Export rechecks read/distribution permissions and verifies stored bytes, WAVE metadata and checksums before emitting the ZIP. It uses private temporary files and bounded streaming instead of loading audio into PHP strings.

`importFrom` accepts a readable ZIP stream, destination workspace/pack UUID, an exact source-asset-to-destination-upload UUID map, and a command key. Before native ZIP parsing, it bounds single-disk ZIP/ZIP64 directory declarations to 1,001 entries and 1 MiB. It rejects ambiguous end records, extra or traversal names, duplicate/encrypted/unsupported entries, missing objects, oversized metadata and excessive compressed/uncompressed bytes. It never extracts filesystem paths. The complete set of new upload declarations is reserved atomically before receiving any audio, so a quota rejection cannot leave a partially accepted plan. New audio passes through the normal authorized chunk uploads, configured scanner and byte-derived verifier before pack persistence; existing ready destination assets are reverified and matched against the manifest. Imported declarations do not grant distribution rights.

Keep destination IDs and the command key stable when retrying an interrupted import. Upload progress is independently durable: a scanner failure or interruption may leave quarantined chunks or already-verified assets, while no incomplete pack is published. Identical chunks resume safely and a completed command replays without another pack revision. Cancelled or conflicting upload IDs require new IDs. Streams remain owned by the caller; rewind before replay and discard partial output if writing fails.

ZIP transport requires 64-bit PHP and `ext-zip`. `MUSIC_MEDIA_ARCHIVE_MAX_AUDIO_BYTES` defaults to 1 GiB of declared uncompressed audio per archive, counting every asset alias to bound import writes and may be configured from 44 bytes to 16 GiB. Each audio object still obeys the existing 1 GiB upload ceiling; input ZIP bytes are additionally capped at the audio limit plus 16 MiB. Local staging may require several times the audio size in free disk space. Run large transfers off request/audio threads; asynchronous archive orchestration remains unfinished.


`UploadBudgets::get(actor, workspace)` returns a schema-v1 immutable reservation view with byte units and requires `music.media.quota_read`. New uploads reserve twice their declared size for quarantine and a future verified object, including duplicates. Allocation, the upload identity and reservation ledger commit atomically. A workspace row lock plus a conditional counter update prevents concurrent allocation from exceeding the policy. Replaying an existing upload does not debit capacity again or apply a reduced limit to already-accepted work. `UploadBudgetExceeded` reports the rejected reservation; local recording and accepted upload append/verification are unaffected.

Set `MUSIC_MEDIA_MAX_RESERVED_BYTES` to a non-negative integer; `0` denies new allocations and the default `null` leaves capacity unlimited while still accounting for reservations. Hosts may bind the public `UploadBudgetPolicy` contract to their canonical workspace entitlement/settings service instead of the provided configuration adapter. No parallel billing or identity model is introduced. Budget events are delivered after commit through `UploadBudgetChanged` with the actor, upload identities, signed byte delta and resulting reserved total.

Cancellation with no retained chunks releases its reservation immediately. If chunks exist, the full reservation remains charged through grace periods, failed deletion, dry runs and partial cleanup pages, and is released exactly once when the final cancelled chunk is acknowledged in the same transaction. Ready and recoverable trashed assets keep their reservations; byte-level deduplication is not a quota discount. This is a conservative declared-upload reservation budget, not a physical disk or billing meter, and does not include ZIP temporary files or render buffers. Explicit ready-asset trash/collection is supported below; discovery of untracked physical orphan objects remains unfinished.

Run the two budget migrations before serving the new upload code. The backfill registers existing uploading/ready assets and cancelled uploads that still have chunks, with database-side aggregation and no deletion of audio. Existing usage may exceed a newly configured limit; it is preserved and reported rather than trimmed. Reversing the accounting schema preserves uploads, media bytes and retention references. Hosts constructing `MediaUploads` or `QuarantineCleanup` manually must supply `UploadBudgets` on the same database connection; container resolution wires it automatically.

`MediaUploads::startBatch` accepts 1–1,000 distinct typed `StartUpload` declarations. It reserves the complete plan in one transaction, returns progress in caller order and rejects cancelled identities. Archive import uses this phase before file I/O; accepted declarations remain resumable if later scanning or transfer fails.

### Asynchronous waveform previews

`WaveformProcessing::request($actor, new RequestWaveform($workspaceId, $taskId, $assetId, $framesPerPeak))` creates an owner-scoped durable task and dispatches `BuildWaveform` after the surrounding SQL transaction commits. Use a stable UUID to replay a request. Changing its asset, source checksum or requested window is a conflict. `get()` returns a schema-v1 task (`queued`, `ready`, `failed`); `result()` returns the cached typed waveform or null without indexing audio in a query. There are no audio bytes, private paths or raw failure messages in task DTOs/events.

Workers resolve the requesting user through the host's configured Laravel `UserProvider` and recheck live asset authorization. Removed users, revoked permission, missing media and invalid bytes fail closed. Three attempts use 5/30/120-second backoff; exhausted attempts mark the task failed. The job timeout is 60 seconds: configure the selected queue's `retry_after` above that timeout, and provision workers for the maximum supported recording sizes. The default Laravel queue connection applies, so a `sync` connection executes inline; select a working asynchronous connection/worker in production. This module does not start or replace Horizon.

`CachedWaveforms` caches derived previews for 24 hours under a schema-versioned key containing the workspace, verified content checksum and requested sample-frame window. Identical assets in one workspace reuse previews; another workspace or window cannot reuse that entry. Every cache access checks current read permission, ready status and source presence. The immutable verified checksum is the cache identity; cached preview reads do not re-hash all source audio. `AssetWaveforms::build()` remains the explicit uncached byte-verifying path. These derived previews are never evidence that audio can be published or distributed.

Replay the same request to retry a failed task, recover a queue-publication outage, or regenerate an evicted preview. A ready task with an evicted/expired cache may return null until replay and worker completion. Duplicate deliveries are safe; successful state changes emit one `WaveformTaskChanged` after commit and a late exhausted duplicate cannot downgrade ready state. Host cache storage must be private/trusted, as for other application cache data. Disablement/rollback removes task metadata only and preserves recordings.


### Recoverable trash and published-asset collection

`AssetLifecycle::trash($actor, new TrashAssets($workspaceId, $assetIds, $commandKey, $graceHours))` atomically moves 1–100 ready entries into trash after checking `music.media.trash` and `read` for each entry. Permanent session/pack references and unexpired offline pins prevent trashing their own asset identities. The default and minimum grace period is 24 hours, measured in UTC; the maximum is one year. There is no automatic deletion of arbitrary unreferenced ready recordings. Stable command keys return immutable historical receipts and do not repeat a transition after recovery or collection. Changed arguments/actors/actions conflict. A failed batch or receipt write rolls back the entire transition.

`list($actor, new ListTrashedAssets($workspaceId, $limit, $afterAssetId))` requires `music.media.trash_list`, then per-asset trash/read permission. It returns a bounded schema-v1 page of names, states and explicit UTC trash/eligibility times without private addresses or retention details. Ready catalogs, uploads, waveform workers and new retention operations cannot consume trashed entries. Use `recover($actor, new RecoverTrashedAsset($workspaceId, $assetId, $commandKey))` with restore/read permission before collection claims the entry. Recovery rechecks the original checksum, byte count and WAVE structure and restores the same identity, metadata and references. Recovery is available after the eligibility time if collection has not started; missing/corrupt audio cannot be recovered from trash.

`AssetGarbageCollection::collect($actor, new CollectTrashedAssets($workspaceId, $limit, $afterAssetId, $dryRun))` requires workspace/per-entry `music.media.collect`. Dry runs are the default, bounded to 100 entries and do not mutate metadata, files or quotas. Real collection first commits a `purging` intent for eligible trash, rechecking retention, then deletes bounded quarantine chunk objects and acknowledges each asset in its own transaction. **Call collection outside any caller-owned SQL transaction.** Once intent commits, recovery and new references are refused. After interruption, restart at the last successfully completed cursor (or from the beginning); retry acknowledges already-missing objects and resumes `purging` entries. Do not advance the cursor from a failed page. A page can make partial progress before throwing.

Publication, trash recovery and collection share a database content-address lock. A collector retains the verified shared object while any ready alias or recoverable trash alias exists in that workspace, including an alias published after intent. Other workspace objects are separate. It verifies ledger addresses before deletion and never follows arbitrary stored paths. SQL/file failures leave committed unreadable tombstones for retry; rolling back acknowledgement cannot make physically removed audio available to a session. Collected identities, provenance, annotations, command receipts and retention audit rows remain; source chunks are removed and the logical reservation is released exactly once after acknowledgement. `declared_bytes` counts logical asset declarations, including aliases, rather than physical freed space. Derived waveform caches may expire naturally and never make a collected identity readable.

`AssetLifecycleChanged` publishes trashed/ready/purging/collected changes after their SQL commit. Run the lifecycle migration before deploying the new publication code; manually constructed `MediaUploads` instances now also require `ContentLocks` on the same connection. Normal container resolution wires it. Schema rollback removes lifecycle metadata/locks but preserves media and terminal statuses; it cannot resurrect deleted recordings. Back up recordings and use forward recovery for installations that have already collected assets. Untracked physical-orphan discovery, general archive orchestration and production scanner/rights-policy integration remain outside this completed lifecycle increment.

### Cursor browsing and waveform cancellation

`MediaCatalog::browse($actor, new BrowseAssets($workspaceId, query: 'kick', tags: ['drums'], limit: 25, beforeAssetId: $cursor))` returns a schema-v1 `AssetPage` with `items` and `next_asset_id`. Pass the returned cursor unchanged for the next page; null ends traversal. Pages use descending asset UUID order, bounded to 100 entries, without a count or offset query. Workspace list and per-entry read permissions are checked on every page. This order is by identity, not recording time; matching concurrent insertions ahead of the cursor appear on a fresh traversal.

`WaveformProcessing::cancel($actor, $workspaceId, $taskId)` cancels an owned queued task, including one currently deriving peaks, and emits its change after commit. Repeated cancellation is safe; request replay and late queue delivery cannot reopen it. Ready/failed tasks reject cancellation. Status reads and cancellation remain available when source audio is missing, with live read permission checks. Versioned task serialization includes terminal/cancellable flags and explicit completed/total waveform-build steps. Cancellation prevents result publication; it does not interrupt an executing CPU operation or delete a shared derived cache.

`MediaCatalog::get($actor, $workspaceId, $assetId)` returns the current authorized annotated name/tags/version and verified audio metadata for a ready catalog identity. It reports source presence through `available`, including missing audio, without turning a metadata read into a verified playback/reference grant. `MediaUploads::get` remains the stricter available-source boundary used by consumers requiring the audio itself.

The core captures its canonical user-provider choice at provider registration, before request authentication can switch Laravel's default guard. Resolution prefers `MUSIC_MEDIA_USER_PROVIDER` (a registered Laravel provider name), then the configured default guard's provider, then the default password broker's provider. Set the explicit provider for hosts with custom identity arrangements. This selection applies to queued waveform work and foundation media access; it does not create a separate Music identity authority or fall back to an arbitrary user table.
